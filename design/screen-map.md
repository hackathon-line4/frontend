# 화면별 인터랙션 메모 (캔버스 메모 원문)

## addSpec

10 신호 추가 · 흐름과 인터랙션 (4단계)

흐름
· 진입: 홈 '+ 신호 추가하기' 또는 신호 탭 '+ 신호 추가'
· 1단계 10-1 → 목록(10-2) 또는 직접(10-3)
  - 목록에서 고른 기본 신호는 리듬이 정해져 있으므로 2단계를 건너뛰고 3단계로 (리듬 변경은 막음, 현장 어휘와 맞추기 위함)
  - 이미 추가한 신호는 '이미 추가됨'(점선)으로 선택 불가
· 2단계 10-4 프리셋 / 10-5 직접 조합하기 (탭으로 전환)
  - 다른 신호가 쓰는 프리셋은 '사용 중 · 신호 이름' 점선으로 선택 불가
· 3단계 10-6: '이 폰에서 느껴보기' = 보호자 휴대폰에서 재생. 재생 중인 박자는 진하게, 남은 박자는 흐리게. '저장하기' → 4단계
· 4단계 10-7: 저장 후 신호 상태는 '연습 전'. '지금 알려주기' → 연습 모드(이 신호부터)

직접 조합하기 (10-5)
· 정해진 박자 3종을 순서대로 붙여 만듦: 짧게 0.2초 / 중간 0.5초 / 길게 0.9초, 박자 사이 간격 0.3초 (값은 기기 테스트 후 확정)
· 최소 2박자, 최대 5박자. 박자 버튼을 누를 때마다 그 박자를 보호자 휴대폰에서 한 번 울려 줌
· 만든 리듬 칸: 순서대로 표시, 방금 넣은 박자는 테두리 강조, 남은 칸은 점선
· '하나 지우기' = 마지막 박자 삭제, '모두 지우기' = 처음부터
· 이미 다른 신호가 쓰는 리듬과 완전히 같으면 '다음' 대신 "'가자'와 같은 리듬이에요" 안내 + 경고 아이콘 (같지 않으면 초록 체크 + '같은 리듬을 쓰는 신호가 없어요')
· 스크린리더: 박자를 넣을 때마다 '중간 추가, 3박자, 약 2.2초' 읽기

접근성
· 리듬 그림마다 '길게 짧게 중간' 같은 대체 텍스트

## authSpec

03 로그인 · 회원가입 · 역할 선택 · 인터랙션

로그인
· 이메일·비밀번호 입력 → '로그인'
· 실패 시 입력창 아래 경고 아이콘 + 오류 문구, 스크린리더 즉시 읽기, 짧은 진동 3회
· 눈 아이콘 버튼으로 비밀번호 보기/숨기기
· '회원가입' → 회원가입 화면
· 로그인 후 역할이 없으면 → 역할 선택 / 있으면 → 해당 역할의 홈

회원가입
· 입력을 마치고 다음 칸으로 이동할 때 유효성 검사
· 상태는 아이콘 + 문구로 표시 (색만으로 구분하지 않음)
· 필수 약관에 동의해야 '가입하기' 활성화. 비활성일 때는 버튼 아래에 "약관에 동의해 주세요" 안내
· 가입 완료 → 역할 선택

역할 선택
· 카드 전체가 하나의 버튼 (높이 200px 이상)
· 보호자 → 계정 연결(04-G1) / 당사자 → 계정 연결(04-R1)
· 역할은 나중에 설정에서 변경 가능

## calSpec

06 진동 보정 · 인터랙션

흐름
06-1 설정 → '진동 테스트' → 06-2 테스트 중 → (끝나면 자동) 06-3 느낌 확인
· '잘 느껴져요' → 06-5 저장 확인 → '설정 저장하기'
· '조금 더 강하게' → 세기 1단계 올리고 바로 다시 테스트. 이미 최대(또는 세기 조절 미지원)이면 06-4로 이동
· '다시 테스트하기' → 같은 설정으로 06-2
· 06-4에서 하나를 고르면 그 값으로 바꾼 뒤 바로 06-2

조작 방식
· 슬라이더 대신 − / + 버튼(64px)과 단계값. 스크린리더는 '세기 강하게, 3단계 중 3'으로 읽음
· 값을 바꿀 때마다 그 값으로 짧은 미리보기 진동 1회
· 최대/최소에서는 버튼 비활성(점선 + 흐린 색) + '최대' 라벨
· 상단 상태: '저장된 설정' / '바꾼 설정 · 아직 저장 안 함'
· 테스트 중: 화면 전체 노란 배경 + '진동 테스트 중' + 진행('2번 중 1번째'). 스크린리더 안내는 진동 시작 전에 끝내고, 진동 중에는 다른 햄틱을 내지 않음

기기 지원 범위 (구현 시 확인)
· 세기: iOS는 Core Haptics 지원 기기, Android는 진폭 제어(hasAmplitudeControl) 지원 기기에서만 표시. 단계 수는 기기 확인 후 결정
· 세기 조절을 지원하지 않으면 세기 칸을 숨기고 '이 기기는 세기를 바꿀 수 없어요' 안내, 길이·반복만 제공
· 길이·반복은 모든 기기에서 패턴 시간을 늘리는 방식으로 구현 가능

신호의 뜻은 고정
· 보정값은 모든 신호에 같은 비율로 적용(전체 세기 · 전체 시간 배율 · 반복 횟수). 신호 안의 짧고 긴 순서와 간격 비율은 바꾸지 않음
· 테스트를 통과해도 '모든 신호를 구분할 수 있다'고 표시하지 않음. 구분 확인은 촉신호 연습으로 연결

다시 보정
· 설정 > 내 진동 설정에서 언제든 06-1부터 다시. 저장하지 않고 나가면 이전 저장값 유지

## homeSpecG

05 보호자 홈 · 신호 탭 · 위치 탭

하단 탭 (5개)
· 홈 / 신호 / 위치 / 기록(08) / 설정(09). 현재 탭은 노란 알약 배경 + 굵은 글자 + aria-current

리듬 표기 (앱 전체 공통)
· 점 = 짧게, 짧은 선 = 중간, 긴 선 = 길게. 기본 크기: 점 9×9, 짧은 선 16×9, 긴 선 26×9, 간격 5px. 크게 보여 줄 때(체험·조합)는 같은 비율로 키움
· 리듬 옆이나 레이블에 '짧게 짧게 길게'처럼 글로도 제공 (스크린리더)
· 와이어프레임의 리듬은 자리 표시용 예시. 기본 신호의 실제 리듬은 현장 촉신호 어휘·전문가 검증 후 확정

배지
· 기본: 흰 바탕 + 검정 테두리 + 책 아이콘 '기본' (현장 촉신호 어휘에서 가져온 신호)
· 직접: 검정 바탕 + 흰 글자 + 연필 아이콘 '직접' (보호자가 만든 신호)
· 채움·아이콘·글자가 모두 달라 색 없이도 구분

홈 (05-1)
1. 당사자 상태: 이니셜·이름·연결 배지 + 마지막 응답과 시각. 응답 대기 시간(설정값, 기본 10분)을 넘기면 카드가 주의 색(주황 바탕 + 경고 아이콘 + '응답 없음 · N분째')으로 바뀜
2. 자주 쓰는 신호: 2×3, 누르면 보내기 확인 시트 → 전송. '+ 신호 추가하기' → 10 신호 추가
3. 위치: 썸네일 + 마지막 업데이트. '자세히 보기' → 위치 탭. 공유가 꺼져 있으면 썸네일 대신 꺼진 핀 아이콘 + '위치 공유 꺼짐'
4. 최근 활동 3건: 응답 완료(초록 체크) / 수신만(회청색 휴대폰: 기기 도착, 터치 응답 없음) / 미확인(주황 물음표: 기기 도착 확인 안 됨) / 실패(빨강 경고). 색 + 아이콘 + 글자
5. 긴급 신호: 탭바 바로 위 고정. 검정 바탕 + 빨간 원 아이콘. 누르면 긴급 신호 고르기 → 확인 후 전송

신호 탭 (05-2)
· 카테고리(일상·외출·확인·긴급)별 묶음. 이름·배지·리듬. 아직 알려 주지 않은 신호는 점선 '연습 전'
· 항목을 누르면 신호 상세(05-4)

신호 상세 · 알려주기 (05-4)
· 아이콘·이름·배지·리듬(크게)·길이
· '알려주기'(노랑): 당사자 휴대폰에 이 리듬을 연습용으로 울림. 보호자가 옆에서 뜻을 알려 주는 용도. 응답을 요구하지 않고, 신호 기록(08)에는 '연습'으로 따로 남김. 당사자 화면에는 수신 화면 대신 연습 표시 (설계 필요)
· 한 번 알려 준 신호는 '연습 전' 표시가 사라짐
· '신호 보내기'(흰색): 실제 신호 전송 → 응답 대기

위치 탭 (05-3)
· 지도 전체 + 핀 1개 + 정확도 원. 이동 경로·과거 위치는 저장·표시하지 않음
· 상단: 공유 상태와 '당사자가 언제든 끌 수 있음' 안내. 하단 시트: 업데이트 시각·주소·정확도·'위치 새로고침'(당사자 휴대폰에 현재 위치 1회 요청)
· 이전 설계(08·09)의 '도움 요청 때만 위치 공유' 정책과 달라짐 → 당사자 동의 화면과 정책 확정 필요

## linkSpecG

04 계정 연결 · 보호자 · 인터랙션

· '연결 코드 만들기' → 6자리 숫자 코드 + QR 생성, 유효 시간 10분
· 코드는 3자리씩 띄워 크게 표시. 스크린리더는 한 자리씩 읽음 ("4, 8, 2, 9, 1, 3")
· 만료되면 코드 영역에 '만료됨' + 아이콘 표시, '새 코드 만들기'를 주 버튼으로 바꿈
· 코드 복사 / 공유하기(문자·메신저로 전달)
· 당사자가 코드를 입력하거나 QR을 인식하면 → 푸시 알림 + 연결 요청 화면(G3)
· G3에서 연결 대상(이름, 역할, 요청 시간, 사용된 코드)을 확인 후 '연결하기' 또는 '거절하기'
· 거절하거나 10분 동안 응답이 없으면 요청 취소, 당사자에게 진동 + 안내
· 연결 완료(G4) → '첫 메시지 보내기' 또는 '홈으로'
· 보호자 한 명이 여러 당사자와 연결 가능 (설정 > 연결 관리)

## linkSpecR

04 계정 연결 · 당사자 · 인터랙션

· 화면마다 할 일은 1~2개, 주요 버튼 높이 72px 이상, 본문 18px 이상
· 코드 입력(R1): 실제 입력창은 숫자 입력창 1개 (스크린리더·점자 디스플레이 호환). 네모 6칸은 시각 표시용
  - 한 자리 입력할 때마다 짧은 진동 1회
  - 6자리가 모두 입력되면 '연결 요청하기' 활성화 + 짧은 진동 2회
· QR 인식(R2): 코드가 화면 가운데에 가까워질수록 진동 간격이 짧아짐. 인식되면 긴 진동 1회 후 R3로 자동 이동
· 연결 대상 확인(R3): 들어오면 "이영희 보호자와 연결할까요?"를 스크린리더로 읽고 짧은 진동 2회
  - '연결하기' → 보호자 승인을 기다리는 동안 "보호자의 확인을 기다리고 있어요" + 대기 진동 없음
· 연결 완료(R4): 완료 진동 패턴(길게 1회 + 짧게 2회), 스크린리더 "이영희 보호자와 연결됐어요"
· 실패(코드 틀림·만료·거절): 짧은 진동 3회 + 경고 아이콘 + "코드를 다시 확인해 주세요"

## logSpec

08 신호 기록 · 정보 구조와 상태 정의

목록 (08-1)
· 날짜 이동: 이전/다음 버튼 + 날짜를 누르면 달력. 오늘 이후로는 이동 불가
· 필터: '전체' / '응답 없음' (aria-pressed로 선택 상태 전달, 선택은 진한 채움 + 체크 아이콘)
· 항목: 신호 이름 · 의미 · 보낸 시각 + '기기 전달'과 '터치 응답' 두 줄을 항상 따로 표시
· 항목을 누르면 상세. 전송 실패 항목에는 '다시 보내기'

상태 정의 (기기 전달)
· 전송 요청 중: 서버에 요청했고 아직 결과 없음 (점선 원)
· 전송 실패: 서버 또는 네트워크 오류로 보내지 못함 (경고 삼각형 + 사유)
· 기기 전달 완료: 당사자 앱이 수신 확인(ack)을 보낸 경우에만. 푸시 알림 발송 성공만으로는 표시하지 않음
· 전달 여부를 알 수 없음: 기기가 꺼져 있거나 오프라인이면 '전달 확인 안 됨'으로 표시 (확인된 것처럼 쓰지 않음)

상태 정의 (터치 응답)
· 응답 대기 중: 전달 완료 후 대기 시간 안 (모래시계 + 경과 시간)
· 응답 완료: 당사자의 명시적 터치가 서버에 기록된 경우만 (체크 + 응답 시각 + 전달 후 걸린 시간)
· 응답 없음: 대기 시간(기본 10분) 동안 터치 기록 없음 (점선 원 X + 점선 카드 테두리)
· 전달 전이거나 전송 실패면 응답 상태를 만들지 않고 이유만 적음

표현 원칙
· '읽음', '이해함', '확인함' 같은 말은 당사자 쪽에 쓰지 않음
· 응답이 늦거나 없을 때는 시간만 객관적으로 적고, 위험·이상 징후 같은 해석을 붙이지 않음
· 보호자 쪽의 '열어 봄'은 보호자 자신의 기록이므로 사용 가능

위치 정보 (08-3)
· 당사자가 도움 요청을 보낼 때 함께 공유된 경우에만 그 요청 상세에 표시
· 요청 순간 1회 위치만 저장, 지속 추적 없음. 일반 신호 기록·목록에는 위치를 표시하지 않음
· 위치 공유 여부와 보관 기간은 당사자 설정에서 결정 (정책 확정 필요)

감시 인상 줄이기
· 기록은 '보낸 신호'와 '받은 요청' 중심. 당사자의 앱 사용 시간, 화면 켜짐, 이동 경로 같은 활동 정보는 기록하지 않음
· 기록 보관 기간과 삭제 방법은 당사자와 보호자 모두에게 공개 (기간 확정 필요)

## obSpec

02 온보딩 · 인터랙션

· 이동: '다음' 버튼 또는 좌우 스와이프. 마지막 장의 '시작하기' → 로그인
· 건너뛰기: 1·2장 오른쪽 위, 누르면 바로 로그인으로 이동
· 페이지 표시: 현재 페이지는 길쭉한 막대 + 진한 색 (모양과 명도로 구분). 스크린리더는 "3페이지 중 1페이지"로 읽음
· 페이지가 바뀔 때 짧은 진동 1회
· 진동 체험(3장): 버튼을 누르면 '밥 먹었어?' 패턴(짧게-짧게-길게)이 1회 재생. 재생 중에는 버튼 라벨이 '진동 중…'으로 바뀌고, 끝나면 '다시 느껴 보기'로 바뀜. 진동을 지원하지 않는 기기에서는 "이 기기는 진동을 지원하지 않아요" 안내
· 체험은 선택 사항: 누르지 않아도 '시작하기' 가능

## recvSpec

07 진동 송신 · 수신 · 응답 · 인터랙션

원칙
· 당사자 화면은 항상 화면 전체가 하나의 터치 영역. 분할 버튼·패널·작은 아이콘·안내 문구 없음
· 상태는 화면 전체의 색과 모양으로 구분: 대기 = 검정 + 노란 고리 / 보내기 = 검정 + 노란 원 속 검정 비행기 / 보냄 = 노랑 + 검정 비행기 / 수신 = 노랑 + 검정 원 / 응답 완료 = 검정 + 큰 노란 체크
· 같은 상태를 스크린리더 레이블·점자 디스플레이·진동으로도 확인 가능 (색만으로 전달하지 않음)

07-1 대기 · 위치가 아니라 조작 방식으로 기능 구분
· 한 번 탭: 전송 없음 (실수 방지). 연결 상태 확인 진동만 재생 (패턴은 검증 후 확정)
· 두 번 탭: 신호 보내기 화면(07-2) 열기. 바로 보내지 않아 실수 전송을 줄임
· 3초 길게 누르기: 도움 요청. 누르는 동안 1초마다 짧은 진동, 3초가 되면 전송. 그 전에 손을 떼면 취소
· 스크린리더 켜짐: 화면 전체가 요소 하나. 레이블 '손울림 대기 중, 이영희 보호자와 연결됨'. 기능은 접근성 사용자 지정 동작(iOS accessibilityCustomActions, Android AccessibilityAction)으로 '신호 보내기', '도움 요청', '설정' 제공
· 연결 상태와 설정은 화면에 그리지 않음. 스크린리더 레이블·사용자 지정 동작·보호자 앱에서 확인하고 관리

07-2 신호 보내기 (송신)
· 검정 화면 가운데에 큰 노란 원(300px)과 검정 비행기, 아래에 보낼 신호 이름. 화면 어디를 눌러도 똑같이 전송 (가운데를 찾아 누를 필요 없음)
· 보낼 신호는 지금은 '보호자 부르기' 1개 (당사자가 보낼 신호 종류는 검증 후 결정)
· 10초 동안 터치가 없으면 보내지 않고 07-1로 돌아감. 3초 길게 누르기(도움 요청)는 이 화면에서도 동작
· 스크린리더: 들어오면 '보호자 부르기 보내기, 두 번 탭해서 보내기' 읽기

07-3 보냄
· 서버가 전송 요청을 받았다고 확인한 뒤에만 표시. 노랑 화면 + 큰 검정 비행기 + '보냈어요'. 확인 진동 1회(패턴 검증 후 확정), 3초 뒤 07-1로
· 서버 전송 실패 시 '보냄'을 표시하지 않고 07-2 유지 + 실패 진동(패턴 검증 후 확정)
· '보냄'은 서버까지 간 것. 보호자 휴대폰에 도착했는지, 보호자가 봤는지는 당사자 화면에 표시하지 않음 (보호자 쪽 기록에서 관리)

07-4 신호 수신
· 진동 재생과 동시에 화면 전체가 노랑 + 가운데 큰 검정 원(신호 이름)으로 바뀜. 신호 진동 반복 (간격·횟수는 검증 후 결정)
· 화면 어디를 눌러도 똑같이 반복 중단 + 응답 전송. 손바닥 접촉 오인을 막는 최소 터치 시간은 테스트로 결정
· 스크린리더: 수신 즉시 포커스 이동, '이영희, 누가 왔어. 두 번 탭해서 응답' 읽기
· 점자 디스플레이: 보낸 사람과 신호 이름 출력
· 소리 안내는 필수 아님 (설정에서 선택)

07-5 응답 완료
· 서버가 터치 응답을 받았다고 확인한 뒤에만 표시. 전송 실패 시 07-4 유지 + 자동 재시도
· 확인 진동 1회(패턴은 검증 후 확정), 스크린리더 '응답했어요'. 3초 뒤 07-1로 자동 복귀

미응답
· 설정된 시간(기본 10분, 검증 필요) 동안 터치가 없으면 반복 진동만 멈추고 당사자 화면은 조용히 07-1 대기로 돌아감. 경고나 추가 조작 없음
· 보호자에게 '응답 없음' 전달 (07-6). 위험 상황이나 신호 미인지로 단정하지 않음

기록 원칙
· 보냄 → 기기에 도착 → 진동 재생됨(기기 보고) → 응답함 / 응답 없음
· '진동 재생됨'은 인지했다는 뜻이 아님
· '응답함'은 명시적인 화면 터치가 확인된 경우에만 기록. 신호를 이해했다는 뜻이 아니라 화면을 터치해 응답했다는 뜻

사용성 검증 전제
· 색·모양의 뜻과 두 번 탭 / 길게 누르기 조작은 처음 사용할 때 보호자와 함께 연습 모드에서 익힘
· 저시력·전맹 당사자가 참여하는 테스트로 조작 방식, 반복 간격, 대기 시간 확정

## setSpec

09 설정 · 연결 관리 · 인터랙션

구조
· 하위 메뉴 없이 한 화면에 섹션으로 나열: 연결 관리 → 진동 설정 → 알림 → 개인정보 및 위치 (촉신호 연습은 설정에 두지 않음)
· 당사자 설정(09-3)은 같은 순서, 글자 20px 이상·행 높이 80px 이상, 설명은 꼭 필요한 문장만
· 당사자는 대기 화면의 스크린리더 사용자 지정 동작 '설정' 또는 보호자와 함께 열어서 들어옴

연결 상태 문구
· 연결됨: 'HH:MM에 연결을 확인했어요' (마지막 확인 시각을 함께 표시)
· 연결 확인 안 됨: 점선 테두리 + 끊어진 고리 아이콘 + 마지막 확인 시각 + 가능한 원인. 위험을 단정하는 말은 쓰지 않음
· '지금 연결 확인하기': 당사자 앱에 확인 요청을 보내고 응답(ack)이 오면 연결됨. 당사자 쪽에는 진동이나 화면 변화를 만들지 않음
· 당사자의 '연결 확인하기': 결과를 상태 문구와 진동으로 알림 (패턴은 검증 후 확정)

진동 설정
· '내 진동 설정' → 06-1 진동 보정, '진동 테스트 다시 하기' → 현재 저장값으로 06-2
· 보호자 화면에는 당사자의 보정 상태를 읽기 전용으로 표시. 보호자가 당사자 설정을 원격으로 바꾸지 않음

알림
· 터치 응답 알림, 응답 없음 알림: 켜기/끄기 (스위치 옆에 '켜짐/꺼짐' 글자)
· 응답 기다리는 시간: 5 / 10 / 30분 (기본 10분, 값은 검증 후 확정). 07의 미응답 기준과 같은 값
· 도움 요청 알림: 항상 켜짐 (끌 수 없음, 정책 확인 필요)

개인정보 및 위치
· 위치는 당사자가 도움 요청을 보낼 때 그 순간 1회만 전송. 위치 공유 설정은 당사자 휴대폰에서만 변경
· 위치 권한 상태는 운영체제 값을 그대로 읽어 표시: 켜짐 / 꺼짐 / 사용 중에만 허용 / 정확한 위치 꺼짐
· 권한이 꺼져 있으면 '휴대폰 설정 열기' → 운영체제의 앱 설정 화면으로 이동 (iOS: 설정 앱의 손울림, Android: 앱 정보 > 권한)
· 백그라운드 위치 권한은 요청하지 않음 (요청 순간에 앱이 위치를 얻는 방식, 구현 시 확인)
· '기록 보관과 삭제': 보관 기간과 삭제 방법 안내 (정책 확정 필요)

01 스플래시 · 인터랙션
