# 10 신호 추가 · 08 기록 · 09 설정

브랜치: `feat/signals-history-settings`. 앞선 보호자 홈·SSE 구현 위에서 이어 작업했다.

## 신호 추가

- 로그인 상태의 신호 탭은 서버 목록을 표시한다. `/signal-templates?linkId=...`의 실제 템플릿 UUID와 alreadyAdded로 선택 가능 여부를 표시한다.
- `/rhythm-presets?linkId=...`의 실제 프리셋을 표시하고, 기존 신호와 진동 배열을 비교한다. 다음 단계 진입 시 `/links/{linkId}/signals/rhythm-check`로 확인하며 저장 시점의 서버 중복 오류도 표시한다.
- 템플릿은 `{source:TEMPLATE, templateId}`, 직접 만들기는 `{source:CUSTOM, name, description, category, icon, rhythm, presetId?}`로 저장한다.
- 생성 요청의 본문·Idempotency-Key를 유지한다. 전송 결과가 불명확한 재시도와 중복 탭은 동일 요청을 공유하고, 실제 생성 응답을 확인한 뒤에만 완료 화면으로 이동한다.
- 저장한 서버 ID를 사용해 목록과 홈을 다시 읽는다. 실패하면 체험 화면에 오류를 표시하며 리듬을 수정할 수 있다. 계정 변경·화면 이탈·백그라운드 후 늦은 성공으로 완료 화면을 열지 않는다.
- 서버 없는 기존 개발 미리보기도 유지한다. 실제 로그인 상태에서는 모의 목록으로 대체하지 않는다.

## 기록

- 날짜 버튼으로 월 달력을 열고 `/links/{linkId}/history/calendar?month=...&tz=...`에서 기록 수와 응답 없음 여부를 읽는다. 선택한 날짜로 목록을 조회하며 오늘 이후 날짜는 선택할 수 없다.
- 날짜별 조회와 달력에 동일한 기기 시간대를 전달한다. 빈 기록·조회 실패·재시도와 응답 없음 필터를 제공한다.
- 응답 완료 상세는 실제 메시지의 전달 시각·재생 보고·터치 시각과 응답 소요 시간을 분리해 표시한다.
- 도움 요청 상세는 실제 열람 확인·도착 기록·주소 텍스트·위치 기준 시각·정확도·후속 신호를 표시한다. 위치가 없거나 주소가 없으면 그 상태를 표시한다. 실제 화면에는 모의 지도 영역을 표시하지 않는다.

## 설정

- 보호자는 `/me/notification-settings`를 읽고 보낸 필드만 PATCH한다. 응답 없음·터치 알림 및 5/10/30분 대기 시간을 저장한다. 도움 요청 알림은 읽기 전용이다.
- 상대 진동 설정과 위치 공유 여부는 `/links/{linkId}/partner-settings`를 사용하며 읽기 전용으로 표시한다.
- 당사자는 `/me/location-sharing`의 값을 읽고 PUT으로 변경한다. 실패 시 이전 서버 확정값을 유지한다.
- 연결 상대 정보·연결 날짜·마지막 확인은 실제 `/me` 연결 정보와 확인 결과를 사용한다. 로그아웃은 기존 서버 로그아웃과 로컬 토큰 삭제를 사용한다.
- 연결 확인은 POST `/links/{linkId}/connection-checks` 후 GET `/connection-checks/{id}`를 조회한다. PENDING을 성공으로 표시하지 않으며 상대 ack 이후 CONFIRMED 또는 서버의 UNCONFIRMED 결과를 반영한다.
- `connection_check.requested`를 받으면 신호 수신 화면이나 진동 없이 별도 조용한 ack 경로를 사용한다. 네트워크 실패는 활성 상태에서 재시도한다. 양쪽 사용자가 같은 대기 요청을 조회한 경우에도 요청을 받은 쪽만 ack한다.
- Android 알림 권한은 기존 네이티브 모듈에서, 위치 권한은 PermissionsAndroid에서 읽는다. iOS·웹·모듈 미지원 환경의 알 수 없는 값은 허용됨으로 꾸미지 않고 휴대폰 설정 확인으로 표시한다. 권한 조회 자체로 권한을 요청하지 않는다.

## 검증과 남은 외부 의존성

2026-11-12: 자동 테스트 79개, 린트·타입 검사, Android Hermes 번들과 아래 로컬 Docker API 검증을 통과했다. 실제 휴대폰 두 대의 UI·진동·권한 전환 검증은 별도다.

- 자동 테스트, 린트, 타입 검사와 Android 번들을 확인한다. 테스트는 저장 본문/키 재사용, 중복 오류, 세션 교체, 달력 경계·윤년, 부분 설정 저장, 실패 시 기존 값 유지, 연결 요청/ack/시간 초과와 주소 표시 모델을 포함한다.
- 로컬 Docker의 backend dev에서 실제 템플릿 추가/직접 만들기/동일 키 재요청/중복 리듬 오류, 날짜·달력·응답 완료·도움 요청 조회, 양쪽 설정과 상대 설정 읽기, 연결 요청·상대 ack·CONFIRMED 및 로그아웃을 확인한다. 테스트 연결과 세션은 종료한다.
- 현재 실행 중인 백엔드 dev에는 연결 확인 요청을 상대 앱에 전달하는 SSE/조용한 푸시 발행이 없다. 프론트의 요청·결과 조회·수신 ack 경로는 준비했지만, 한쪽에서만 누른 연결 확인을 상대 앱이 자동으로 수신하는 전체 흐름은 백엔드 발행 코드 통합 후 실기기로 확인해야 한다.
- 실제 위치 수집/전송과 FCM 기기 등록·수신은 기존 별도 기능 범위다. 이 변경은 서버의 위치 공유 설정과 이미 도움 요청에 저장된 주소를 다룬다. 위치 권한이 켜졌다는 사실만으로 위치를 전송했다고 표시하지 않는다.
- 별도 연습 신호 생성 API가 현재 dev에 없어 실제 저장 완료 화면은 신호 확인으로 연결한다. 연습 전 여부는 서버의 practiced 값을 사용한다.

## 2026-11-13 설정 보완

- 내 진동 보정은 서버 저장 응답을 확인한 뒤 적용하고 설정 화면으로 돌아간다. 저장 중 중복 탭을 막고, 실패하면 기존 적용값과 작성값을 유지하며 다시 저장할 수 있다.
- 반복 횟수 선택·저장·복원 범위를 서버와 같은 1~5회로 맞췄다. 잘못된 서버 응답은 정상 보정값으로 적용하지 않는다.
- 보정 캐시는 사용자 ID별로 저장한다. 기존 공용 캐시는 소유자를 알 수 없어 가져오지 않고 서버에서 복원한다. 계정 전환 시 저장값·작성값을 초기화하며 이전 세션과 취소된 요청의 늦은 응답을 무시한다.
- 알림·위치 권한을 각각 조회하여 한쪽 오류가 다른 쪽 결과를 지우지 않게 했다. 앱 복귀·화면 이탈 이후 오래된 권한 조회가 최신 결과를 덮어쓰지 못한다.
- 자동 회귀 테스트는 보정 저장 실패·재시도, 계정별 복원, 계정 교체·취소·조회 순서 경쟁, 반복 1~5회, 권한별 오류와 앱 복귀 시 최신 결과 유지 등을 포함한다.

APK 실기기 확인 항목(아직 미검증):

1. 보정 반복 4·5회를 저장하고 앱 재시작 후 값과 실제 진동을 확인한다. 네트워크를 끊고 저장하면 오류가 표시되고, 복구 후 같은 작성값으로 다시 저장되는지 확인한다.
2. A 계정에서 보정 후 B 계정으로 로그인하여 값이 섞이지 않는지 확인한다. 다시 A로 로그인하여 A의 저장값을 확인한다.
3. 설정 앱에서 알림을 허용·거부한 뒤 앱으로 복귀하여 표시가 갱신되는지 확인한다.
4. 위치 담당자의 권한 선언·요청이 포함된 APK에서 정확한 위치·대략적 위치·거부 각각의 표시와 복귀 시 갱신을 확인한다. 이 변경은 위치 수집·공유를 추가하지 않는다.
