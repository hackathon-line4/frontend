# 07 당사자 보내기와 수신 보고

기존 API 클라이언트와 로그인 세션을 사용한다. 실제 로그인한 당사자와 연결된 `ACTIVE` 연결 ID가 없으면 생성 요청을 보내지 않으며 성공 진동·완료 화면을 표시하지 않는다.

| 동작 | 요청 (`/api/v1` 아래) |
| --- | --- |
| 07-2 두 번 탭 | POST `/links/{linkId}/recipient-signals`, `{ type: 'CALL_GUARDIAN', sentAt }` |
| 3초 길게 누르기 | POST `/links/{linkId}/help-requests`, `{ sentAt, locationStatus: 'UNAVAILABLE', location: null }` |
| 놓친 신호 복원 | GET `/messages/incoming` |
| 신호 도착 확인 | POST `/messages/{id}/ack`, `{ receivedAt }` |
| 진동 재생 보고 | POST `/messages/{id}/playback`, `{ count }` |
| 07-4 터치 응답 | POST `/messages/{id}/response`, `{ touchedAt }` |

## 보내기

- 서버가 실제 생성 ID와 연결 ID를 반환한 뒤에만 `playFeedback('sent')`와 07-3 보냄 화면으로 이동한다. 실패 시 `failed` 진동을 울리고 현재 화면을 유지한다.
- 생성 요청은 Idempotency-Key를 사용한다. 중복 터치는 같은 진행 중 요청을 공유하고, 네트워크 실패·취소 후 수동 재시도는 **원래 본문과 같은 키**를 재사용한다. 새 전송에는 새 키를 쓴다.
- 전송 중에는 중복 입력과 07-2의 자동 복귀 타이머를 멈춘다. 화면 이탈·백그라운드 전환 시 요청을 취소하고 늦은 응답으로 화면을 바꾸지 않는다.
- 위치 취득은 이번 범위에 포함하지 않는다. 위치 없이 긴급 요청을 즉시 보내며, 서버는 위치 공유가 꺼져 있으면 `NOT_SHARED`로 저장한다. 추후 위치 모듈과 `/help-requests/{id}/location` 연동은 별도 작업이다.

## 수신과 응답

- 당사자 앱이 활성화되어 있으면 SSE로 신호를 받고 5초 간격으로 놓친 신호를 복구 조회한다. 수신 화면 처리 중에는 추가 조회를 쉬고, 다음 신호는 현재 처리가 끝난 뒤 연다. SSE와 FCM은 같은 `handleIncoming` 입구를 사용한다. SSE 구현과 현재 백엔드의 이벤트 발행 제한은 [보호자·실시간 연동](guardian-realtime.md)을 참고한다.
- 동일 세션의 SSE·FCM·조회 중복 ID는 한 번만 처리한다. 캐시는 256개로 제한하고 세션이 바뀌면 이전 수신 내용을 표시하지 않는다.
- 응답을 처리하는 동안 들어온 신호는 대기열에 보관해 현재 응답 재시도를 덮어쓰지 않는다. 대기 중 긴급 신호를 먼저 열고, 메모리 대기열을 초과한 신호는 서버 조회로 복구한다.
- ack를 먼저 보내고 서버의 `waitUntil`로 대기 종료 시각을 정한다. 일시적인 통신 실패 시에는 신호 진동을 숨기지 않고 ack를 재시도한다.
- 네이티브 진동 모듈에서 실제 재생을 시작한 반복마다 누적 횟수를 보고한다. 네이티브 모듈이 없는 웹·Expo Go에서는 재생했다고 보고하지 않는다. 서버 정책의 최대 재생 시간에도 진동을 중단한다.
- 터치하면 반복 진동을 멈추고 응답을 보낸다. 네트워크·시간 초과·429·5xx는 1/2/4/8/16/30초 간격으로 재시도하며 동일한 최초 터치 시각을 유지한다. 화면이 가려지거나 백그라운드로 가면 취소하고, 복귀하면 이어 보낸다.
- `RESPONDED`와 응답 시각이 확인된 뒤에만 확인 진동과 07-5로 이동한다. 영구 오류는 자동 반복하지 않고 실패 진동 후 다시 터치할 수 있게 한다.
- 연습 신호 터치는 응답 API를 보내지 않고 닫는다. 시간 초과 시에는 조용히 대기로 돌아가며, '응답 없음' 상태는 서버가 판정한다.
