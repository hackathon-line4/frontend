# 계정 연결 API 연동

## 구현 범위

- 04-G2: 현재 코드 조회, 코드 생성·재발급, 서버 `expiresAt` 기준 카운트다운, 만료 시 복사·공유 비활성화.
- 04-R1: 6자리 코드 검증, 없는 코드·만료·시도 제한 오류 표시. 코드 확인은 연결 요청을 생성하지 않는다.
- 04-R3: 실제 보호자 확인 → 연결 요청 생성 → 승인 대기, 취소. 요청 생성 후 반환받은 ID로 상태를 조회한다.
- 04-G3: 대기 요청 목록 조회 → 상대 확인 → 승인·거절. 승인·거절·취소가 경합해 409가 오면 요청을 다시 조회한다.
- 04-G4 / 04-R4: 서버가 `APPROVED`와 실제 `link`를 반환한 경우에만 완료 화면. 상대 이름과 연결을 현재 세션에 반영한다.
- 역할 선택 응답의 새 access/refresh 토큰을 저장한다. 이전 역할 없는 토큰을 계속 쓰지 않는다.
- 연결 화면은 로그인과 역할을 검사한다. 버튼 연속 클릭을 막고 생성 요청 재시도는 같은 Idempotency-Key를 사용한다.
- 상태는 `PENDING`, `APPROVED`, `REJECTED`, `CANCELED`, `EXPIRED`를 구분한다. 요청이 없다는 이유로 성공 처리하지 않는다.

## 필요한 백엔드

2026-11-10 확인: backend `dev`의 `d6c32b3`에는 코드 생성·현재 코드 조회·verify만 있다.
전체 연동은 `origin/feat/37-link-request`의 요청 API가 포함된 서버가 필요하다.
프론트 작업은 `feat/account-link` 브랜치에 있고 백엔드 작업 브랜치를 변경하거나 병합하지 않았다.

| 요청 | API (`/api/v1` 아래) |
| --- | --- |
| 코드 생성·재발급 | POST `/link-codes` (Idempotency-Key 필수) |
| 현재 코드 | GET `/link-codes/current` |
| 코드와 보호자 확인 | POST `/link-codes/verify`, `{ code }` |
| 연결 요청 | POST `/link-requests`, `{ code }` (Idempotency-Key 필수) |
| 받은 요청 | GET `/link-requests?status=PENDING` |
| 상태 조회 | GET `/link-requests/{id}` |
| 승인·거절·취소 | POST `/link-requests/{id}/approve`, `/reject`, `/cancel` |

화면이 보이고 앱이 활성 상태일 때만 5초 간격으로 상태를 조회한다. 복귀 시 즉시 재조회하며 화면 이탈 시 조회를 중단한다.
SSE·푸시 알림과 QR 카메라 인식은 이번 범위에 포함하지 않는다.

## 실행과 실기기 확인

1. 연결 요청 API가 포함된 백엔드에서 PostgreSQL과 Spring Boot를 실행하거나 해당 테스트 서버 주소를 받는다.
2. 프론트 `.env.local`에 휴대폰에서 접근 가능한 `EXPO_PUBLIC_API_URL`을 설정한다. PC 로컬 서버는 휴대폰의 localhost 대신 PC LAN 주소를 사용한다.
3. 필요한 네이티브 모듈이 포함된 development APK에서 `npx expo start --dev-client`로 프로젝트를 연다.
4. 보호자·당사자 계정 두 개로 로그인하고 역할을 선택한다. 역할 선택 이후 새 토큰으로 연결 API가 호출되는지 확인한다.
5. 보호자 설정 → 계정 연결 → 코드 만들기. 당사자 홈 → 연결 코드 입력 → 보호자 확인 → 연결하기.
6. 보호자에 요청이 표시되면 승인. 양쪽 완료 화면과 홈·설정의 상대 이름을 확인한다.
7. 별도 미연결 계정으로 거절, 당사자 취소, 코드 재발급 후 이전 코드 입력, 10분 코드 만료, 요청 만료, 통신 실패 후 재시도, 대기 중 백그라운드 복귀를 확인한다.
8. 중복 승인·취소 경합 시 성공을 추정하지 않고 서버의 최종 상태를 따르는지 확인한다.

## 서버에 남아 있는 연동 조건

- `/me`는 확인한 `dev`와 요청 브랜치 모두 `links: []`, `pendingLinkRequest: null`을 고정 반환한다.
- 승인 직후 연결은 현재 앱 세션에 적용하지만, `/me` 재조회·앱 재시작·재로그인 시에는 서버 응답이 우선한다. **서버가 실제 연결과 대기 요청을 반환해야 자동 복원을 완성할 수 있다.** 앱에서 서버 상태를 추측하는 영구 연결 캐시는 만들지 않는다.
- 요청 ID는 현재 화면 파라미터와 세션에 유지한다. 서버의 대기 요청이 `/me`로 내려오면 재실행 후에도 그 ID로 상태를 확인한다.
- 홈의 상대 이름·연결 유무는 실제 세션을 사용한다. 신호 전송·위치·기록 등 기존 mock 기능은 이번 연결 API 작업과 별도다.
- 백엔드 요청 브랜치는 1:1 연결, 코드 10분·요청 생성 후 별도 10분 유효로 구현되어 있다.
